# Безопасность

## Модель угроз

| Угроза | Защита |
|---|---|
| Взлом сервера или утечка базы | Всё содержимое зашифровано на клиенте, ключей на сервере нет |
| Администратор VPS или хостер | То же: видны только размеры, время и имя автора |
| Перехват трафика | HTTPS, HSTS |
| Превью ссылок в мессенджерах | Ключ во фрагменте `#` не уходит на сервер. Одноразовые заметки открываются только по кнопке |
| Вредоносный контент в заметке | Код не исполняется, Markdown санитизируется, строгий CSP |
| Подбор токена | 256-битные токены, сравнение за постоянное время |

## Чего Arca не защищает

- **Утечку самой ссылки.** Ссылка = ключ. Кто её получил, тот прочитает заметку до конца срока
- **Заражённое устройство** автора или читателя
- **Подменённый сервер.** Если злоумышленник контролирует сервер, он может отдать изменённый JavaScript. Это общая проблема всех веб-сервисов с шифрованием в браузере. CLI от этого защищён: код работает локально
- **Метаданные.** Сервер знает, сколько заметок создал каждый пользователь, их размеры и время

## Как устроена защита

### Шифрование

- AES-256-GCM через WebCrypto, встроенный в браузеры и Node
- Свой случайный ключ на каждую заметку, свой IV на каждый текст и файл
- GCM проверяет целостность: изменённый шифротекст не расшифруется

### Сервер

- Создавать заметки могут только пользователи из `ARCA_USERS`
- Чужую заметку нельзя изменить или удалить: для неё сервер отвечает `404`, как для несуществующей
- Одноразовая заметка отдаётся только через `POST` и стирается в той же транзакции
- Файлы отдаются как `application/octet-stream`: SVG и HTML не исполнятся в браузере

### Браузер

- Markdown проходит через DOMPurify, теги `<style>` и `<form>` запрещены
- Строгий CSP: только свои скрипты, без inline-кода и `eval`
- Внешние картинки в Markdown заблокированы CSP, читатель не раскрывает свой IP сторонним сайтам
- `Referrer-Policy: no-referrer`, `noindex`, запрет встраивания во фреймы

### Инфраструктура

- systemd-сервис изолирован: пишет только в `/opt/arca/data`, без доступа к `/home`, устройствам и ядру
- Код принадлежит `root`, сервис не может его изменить
- Caddy не пишет access-лог: IP читателей нигде не сохраняются
- Сервер без внешних npm-зависимостей: меньше поверхность для атаки через цепочку поставок

## Советы

- Храни код доступа в менеджере паролей
- На чужом компьютере после работы жми «Выйти»: код и черновик лежат в `localStorage`
- Для паролей и секретов включай «Сжечь после прочтения» и короткий срок
- Отправляй ссылку и пояснение к ней разными каналами, если это важно
